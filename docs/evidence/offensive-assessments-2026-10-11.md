# API·소스 진단 확장 검증 — 2026-10-11

탐지·Splunk·Defensive·Closed-loop 구현은 이번 작업에서 변경하지 않았다. 기존 수정사항은 보존하고 Offensive의 선택형 진단 환경·API·웹 UI·Skill만 추가했다.

## 실제 도구 실행

| 환경 | 웹 실행 ID | 확인한 결과 |
|---|---|---|
| crAPI + Schemathesis 4.30.1 | `f2a4439b-fab8-404d-bb1a-0410eb52fc56` | 실습 계정 인증 성공, API 6개, 실제 HTTP 응답 10건, 응답 검사 후보 2건, 도구 오류 0건 |
| Benchmark Java + Semgrep 1.180.0 | `5e3ce9e5-5300-40b3-a8a8-6846c7f84594` | Java 파일 2,740개, 정적 검토 후보 945건, 웹 표시 100건, 분석 오류 0건 |

두 실행 모두 웹의 시작 버튼으로 실행하고 완료 상태·후보·한계·다운로드를 확인했다. 원본 분석 결과와 후보 숫자를 합성하지 않았다. 실행별 근거 파일의 SHA-256을 확인했고, 브라우저에서 내려받은 `report.json`도 저장된 파일과 일치했다.

초기 도구 통합 확인으로 소스 실행 `dc5eb666-c01d-444e-a7f9-d3347a8fde40`, API 실행 `dd1dfee6-19d2-4976-abab-6fc4c9cf0eac`도 보존했다. 초기 API 설정은 100초 반복으로 288개 응답을 기록했다. 최종 기본값은 반복을 제거하고 API 작업당 최대 5개 예제와 125초 프로세스 제한을 사용한다. 첫 실패에서 예제 생성이 멈출 수 있어 작업 수 × 5와 실제 응답 수가 같을 필요는 없다.

## ARTEX 연결

초기 소스 실행에서 **ARTEX 심층 검토 시작**을 눌러 기존 Planner·Worker 작업 `5`를 생성했다. 연결된 작업 링크, Planner의 제약·목표·조사 의도 생성, Worker의 `source-assessment/SKILL.md` 실제 읽기까지 확인했다. Planner·Worker에 두 신규 Skill이 등록됐고, 앱 안에서 보고서와 읽기 전용 소스를 읽을 수 있다.

이 기록은 AI 검토의 최종 취약점 판정 완료나 실제 악용 성공을 증명하지 않는다. 도구 후보를 확정 취약점으로 승격하지 않으며, 모델 실행 상태와 최종 판정은 연결된 ARTEX 작업에서 확인한다.

## 자동 검증

- 배포용 웹 정적 빌드 및 Go 빌드 성공, TypeScript 검사 통과.
- 격리 PostgreSQL 통합 테스트: 하위 테스트 포함 **358개 PASS**, 새 Offensive 테스트 7개 포함.
- 실행기 테스트 **11개 PASS**: 대상 제한, 인증, 비밀값 제거, OpenAPI 구조 보존, 시간 제한, 재시작 복구, 증거 해시·경로 검증, 작업 중복 연결 방지.
- 최초 통합 실행에서는 기존 Splunk 응답 스트림 테스트 2개가 읽기 중단으로 실패했다. 해당 코드는 수정하지 않았으며 전체 재실행은 통과했다.
- 추가 코드 비밀 검사에서 발견된 1건은 `OFFENSIVE_CRAPI_REVISION`의 공개 Git 커밋 SHA였다. 실제 API 키·토큰 파일은 추가 코드에 포함되지 않았다.
- crAPI, 실습 메일, 새 ARTEX 웹 경로의 localhost HTTP 응답 200 확인.

## 해석 범위

API 2건은 응답 스키마 불일치 후보다. 보안 영향이나 침해 성공을 의미하지 않는다. Semgrep 945건은 제한된 5개 규칙에 일치한 정적 검토 후보이며, 945개의 확정 취약점이라는 뜻이 아니다. Benchmark 정답표는 진단 입력으로 사용하지 않았고 정확도·재현율을 산출하지 않았다.

실습 원문·접근 토큰·DB는 Git에서 제외되는 로컬 경로에 보관한다. 공개 문서에는 결과 요약과 [API 화면](images/offensive-api-assessment-20261011.jpg), [소스 화면](images/offensive-source-assessment-20261011.jpg)만 포함한다.
